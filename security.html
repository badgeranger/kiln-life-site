Data and AI working approach

Start with less access. Add only what the decision requires.

This page describes Kiln’s default engagement approach. Exact controls, tools and contractual terms are agreed for each client before confidential data or production systems are involved.

The default

Use synthetic, redacted or aggregated information during early discovery whenever possible. Do not request broad system access to answer a narrow question.

Kiln does not currently claim ISO 27001, SOC 2 or another security certification. Client requirements that depend on formal certification should be identified before engagement.

1. Data minimisation

Define the decision first, then identify the smallest evidence set needed. Sensitive fields should be removed or aggregated where they do not affect the analysis.

2. Synthetic-first prototyping

Models, dashboards and workflows can be structured with synthetic data before real records are introduced. The public sample follows this approach.

3. Agreed tools and providers

AI models, cloud tools and collaboration services are listed and agreed before client data is processed through them. A client-approved stack takes precedence over a default preference.

4. No client-data training by Kiln

Kiln does not use client confidential information to train Kiln-owned models or create public examples. Provider-level data handling must still be reviewed for the tools selected.

5. Least-privilege access

Where access is necessary, it should be time-bounded, role-appropriate and limited to the relevant workspace, source or environment.

6. Human review

AI-generated analysis is treated as a draft or signal, not an autonomous business decision. Material recommendations retain source references, assumptions and a named human reviewer.

7. Retention and deletion

What is retained, where it is stored, who can access it and when it is deleted are defined in the written scope or applicable data-processing terms.

8. Confidentiality

An NDA or client confidentiality terms can be agreed before confidential material is shared. Public portfolio material is created only from approved or anonymised information.

9. Ownership and handover

Ownership of client-specific documents, prototypes, code and configuration is stated in the proposal or agreement. Handover should include editable source files where included in scope.

10. Prototype vs production

A prototype is not represented as a production system. Production work requires explicit requirements for security, reliability, monitoring, access, legal review and ongoing ownership.

Before access

Five questions are answered in writing.

01
What decision requires this data?

The purpose and minimum fields are identified.

02
Where will it be processed?

Tools, model providers, locations and workspaces are named.

03
Who can access it?

Roles, accounts and permissions are limited.

04
How will output be checked?

Sources, evaluation, review and escalation are defined.

05
When will it be removed?

Retention, return and deletion are agreed.

Have a procurement or data question?

Send the requirement before sharing sensitive material. Kiln can confirm fit, identify gaps or propose a synthetic-first starting point.
